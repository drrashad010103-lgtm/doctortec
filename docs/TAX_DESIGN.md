# تصميم الضريبة — Tax Design

**الحالة:** تصميم معتمد كمتطلب عمل (قرار Q-17/Q-18 بتاريخ 2026-10-28)،
**التنفيذ يبدأ في المرحلة 2/4** بعد اعتماد تقرير المرحلة 1.
**النطاق:** ضريبة القيمة المضافة على البيع والشراء والمرتجعات، وفاتورة
ضريبية قابلة للطباعة، وتقارير ضريبية. **تكامل ETA الحكومي مؤجَّل** مع
تجهيز كل حقوله.

---

## 1. القرارات

| # | القرار | الحالة |
|---|---|---|
| T-01 | الأسعار المعروضة **شاملة الضريبة** افتراضيًا (سعر الرف = ما يدفعه العميل) | افتراضي قابل للضبط |
| T-02 | النسبة الافتراضية **14%** قابلة للتغيير من الإعدادات | قابل للضبط |
| T-03 | لكل صنف **تصنيف ضريبي** (14% / 0% / معفى) وليس نسبة حرة | معتمد |
| T-04 | الضريبة تُحسب على **صافي البند بعد خصم البند وخصم الرأس الموزَّع** | معتمد |
| T-05 | تُحفظ نسخة من النسبة والمبلغ في البند (`tax_rate`, `tax_amount`) | معتمد |
| T-06 | تغيير النسبة **لا يغيّر** الفواتير السابقة | معتمد |
| T-07 | المرتجع يعكس ضريبة الأصل بنفس النسبة | معتمد |
| T-08 | تكلفة البيع تُخزَّن **بدون الضريبة القابلة للخصم** | معتمد |
| T-09 | الفاتورة الضريبية تطبع رقم التسجيل الضريبي وQR | معتمد |
| T-10 | إرسال ETA الفعلي لاحقًا؛ الحقول والتوقيع جاهزة | مؤجَّل |

> **قرار مالك مطلوب (سطر واحد):** هل الأسعار الحالية شاملة 14% أم غير
> شاملة؟ التوصية: **شاملة**، لأن سعر الرف هو ما يدفعه العميل. إن كانت
> غير شاملة فسينتج عن تشغيل الضريبة زيادة 14% في الفاتورة، وهذا تغيير
> تسعير يجب أن يعتمده المالك صراحةً.

## 2. الواقع الحالي (لماذا هذا تصميم جديد)

- `currencies.tax` موجود لكن **قيمته 0 لكل 29,595 صنفًا**.
- `companies.tax_no` فارغ، و`tax_pct = 0`، والفاتورة الحالية تطبع رقم
  ضريبي فارغ إن وُجد.
- `inv.tax`, `inv.tax_ats`, `inv_sub.taxperc`, `inv_sub.taxval`,
  `inv.tab3tax` **لا تُحسب ولا تُحفظ** من شاشات البيع/الشراء.
- لا تقرير ضريبي، ولا قيد ضريبة، ولا QR.

**النتيجة:** الضريبة ميزة نائمة. تشغيلها الآن يعني اتفاقًا محاسبيًا جديدًا
على توزيع الإيراد (صافي مبيعات + ضريبة مستحقة)، وليس مجرد إظهار حقل.

## 3. شجرة الحساب (Pipeline) — بالترتيب الإلزامي

لكل بند، وبالـ`decimal` فقط:

```text
1) qty            = الكمية (DECIMAL 18,4)
2) unit_price     = السعر المُدخل (شامل أو غير شامل حسب T-01)
3) gross          = qty × unit_price
4) line_discount  = خصم البند (مبلغ أو %)
5) net_line       = gross − line_discount
6) header_share   = توزيع خصم الرأس بنسبة net_line / Σ net_line
7) net_after      = net_line − header_share
8) tax_rate       = نسبة التصنيف وقت الترحيل
9) إن كانت الأسعار شاملة:
      tax_amount  = ROUND(net_after × rate / (100 + rate), 2)
      tax_base    = net_after − tax_amount
      line_total  = net_after
   وإلا:
      tax_base    = net_after
      tax_amount  = ROUND(tax_base × rate / 100, 2)
      line_total  = tax_base + tax_amount
10) invoice.tax_total = Σ line.tax_amount
    invoice.tax_base  = Σ line.tax_base
    invoice.total     = Σ line.line_total
```

### 3.1 التقريب

- كل الحسابات بـ`Decimal`، والتقريب النهائي `MidpointRounding.AwayFromZero`
  إلى منزلتين.
- **لا تقريب على مستوى الفاتورة ثم توزيعه**؛ الضريبة تُجمع من البنود،
  وبذلك `Σ line.tax = invoice.tax_total` دائمًا.
- توزيع خصم الرأس: طريقة **أكبر باقٍ** (Largest Remainder) وآخر بند يستوعب
  فرق القرش، حتى لا يضيع أو يُضاف مبلغ.
- فروق التقريب النقدية (مثل 0.25 جنيه) تُسجل في `rounding_amount` منفصلة،
  ولا تُخلط بالضريبة.

### 3.2 مثال مرجعي (اختبار إلزامي)

سعر شامل 100.00، ضريبة 14%:

```text
tax_amount = ROUND(100 × 14 / 114, 2) = 12.28
tax_base   = 100 − 12.28           = 87.72
total      = 100.00
```

سعر شامل 100.00، خصم بند 10%:

```text
net_after  = 90.00
tax_amount = ROUND(90 × 14 / 114, 2) = 11.05
tax_base   = 78.95
total      = 90.00
```

## 4. مخطط البيانات المضاف

```text
tax_categories(
  id, code UNIQUE,                 -- vat14 / vat0 / exempt
  name_ar, name_en,
  rate DECIMAL(6,3) NOT NULL,      -- 14.000 / 0.000
  is_exempt BOOLEAN NOT NULL DEFAULT 0,
  is_active BOOLEAN NOT NULL DEFAULT 1,
  effective_from DATE NOT NULL,
  effective_to DATE NULL,
  created_at, updated_at, updated_by
)

items(
  ...,
  tax_category_id BIGINT NOT NULL, -- FK → tax_categories
  ...
)

invoices(
  ...,
  tax_base_total DECIMAL(18,2) NOT NULL DEFAULT 0,
  tax_total      DECIMAL(18,2) NOT NULL DEFAULT 0,
  price_mode     ENUM('inclusive','exclusive') NOT NULL,
  seller_tax_no  VARCHAR(64) NULL, -- نسخة وقت الإصدار
  buyer_tax_no   VARCHAR(64) NULL,
  buyer_name     VARCHAR(255) NULL,
  buyer_address  VARCHAR(255) NULL,
  eta_uuid       CHAR(36) NULL,
  eta_status     ENUM('not_required','pending','submitted','accepted','rejected')
                 NOT NULL DEFAULT 'not_required',
  eta_submitted_at DATETIME NULL,
  qr_payload     TEXT NULL,
  ...
)

invoice_lines(
  ...,
  tax_category_id BIGINT NOT NULL, -- نسخة وقت البيع
  tax_rate        DECIMAL(6,3) NOT NULL,
  tax_base        DECIMAL(18,2) NOT NULL,
  tax_amount      DECIMAL(18,2) NOT NULL,
  price_mode      ENUM('inclusive','exclusive') NOT NULL,
  cost_at_sale    DECIMAL(18,4) NULL,   -- بدون ضريبة قابلة للخصم
  cost_at_sale_incl_tax DECIMAL(18,4) NULL,
  ...
)

settings(
  'tax.prices_include_tax' = '1',
  'tax.default_category'   = 'vat14',
  'tax.registration_no'    = '',
  'tax.recoverable'        = '1',   -- هل المنشأة مسجلة وتخصم ضريبة المدخلات؟
  'tax.rounding'           = 'away_from_zero'
)
```

**قيود إلزامية:**

- `CHECK (tax_rate >= 0 AND tax_rate <= 100)`.
- `CHECK (tax_amount >= 0)` للفواتير العادية؛ البنود السالبة (مرتجع) تحمل
  إشارة سالبة مسموحة.
- `tax_total = SUM(invoice_lines.tax_amount)` يُتحقق في الخدمة قبل الترحيل.
- لا تعديل على `invoice_lines.tax_*` بعد `posted`.

## 5. سياسة الضريبة على الشراء والتكلفة

| الحالة | تكلفة البند | ضريبة المدخلات |
|---|---|---|
| المنشأة مسجلة (`tax.recoverable=1`) | سعر الشراء **بدون** الضريبة | تُسجل قابلة للخصم |
| غير مسجلة | سعر الشراء **شامل** الضريبة | لا تُخصم، تبقى في التكلفة |
| صنف معفى | حسب الفاتورة | صفر |

- `cost_at_sale` يتبع سياسة **آخر سعر شراء حتى تاريخ البيع** (قرار Q-06)
  بعد استبعاد الضريبة القابلة للخصم.
- يُحفظ أيضًا `cost_at_sale_incl_tax` للمراجعة.
- الربح = `net revenue (excl tax) − COGS (excl tax)`؛ المرتجعات تُخصم.

## 6. المرتجعات والإلغاء

- المرتجع فاتورة جديدة بنوع `sale_return`، بنودها سالبة، ومرتبطة
  بـ`original_invoice_id`.
- تُنسخ `tax_rate` من بند الأصل (لا تُستخدم النسبة الحالية).
- `tax_amount` سالب، وتُخصم من تقرير ضريبة المخرجات.
- المرتجع الجزئي: الكمية المرتجعة فقط.
- الإلغاء بعد الترحيل لا يحذف؛ يُنشئ قيدًا عكسيًا/إشعارًا دائنًا.
- لا يُسمح بمرتجع يتجاوز الكمية الأصلية ولا قيمته الضريبية.

## 7. الفاتورة الضريبية — الحقول المطبوعة

| المجموعة | الحقول |
|---|---|
| البائع | الاسم التجاري، الاسم القانوني، رقم التسجيل الضريبي، العنوان، رقم الفرع |
| المشتري | الاسم، رقم التسجيل الضريبي (لـB2B)، العنوان |
| المستند | نوع الفاتورة، الرقم، `uuid`، التاريخ/الوقت، العملة، طريقة الدفع |
| البنود | الوصف، الكمية، الوحدة، سعر الوحدة، الخصم، النسبة، الضريبة، الإجمالي |
| الإجماليات | الإجمالي قبل الضريبة، الخصم، الضريبة، الإجمالي شامل الضريبة، المدفوع، المتبقي |
| الإلكتروني | QR (TLV base64)، حالة الإرسال، `eta_uuid` عند التفعيل |

**QR (متوافق مع نمط ETA):**

```text
Tag 1: اسم البائع
Tag 2: رقم التسجيل الضريبي
Tag 3: الطابع الزمني (ISO 8601)
Tag 4: الإجمالي شامل الضريبة
Tag 5: إجمالي الضريبة
→ كل قيمة TLV (Tag/Length/Value) ثم Base64
```

> التوليد محلي الآن. **الإرسال إلى ETA** يحتاج تسجيل المنشأة، شهادة/توقيع،
> وبيئة اختبار حكومية — خارج نطاق هذه المرحلة.

## 8. التقارير الضريبية

| التقرير | الأعمدة | الفلترة |
|---|---|---|
| إقرار ضريبة القيمة المضافة | فترة، ضريبة مخرجات، ضريبة مدخلات، الصافي المستحق | شهر/ربع سنة |
| سجل الفواتير الضريبية | رقم، تاريخ، عميل، رقم ضريبي، وعاء، نسبة، ضريبة، إجمالي | فترة/فرع |
| ضريبة المشتريات | مورد، رقم ضريبي، وعاء، ضريبة، إجمالي | فترة/فرع |
| الضريبة حسب التصنيف | تصنيف، نسبة، وعاء، ضريبة | فترة |
| المبيعات المعفاة | سبب الإعفاء، وعاء، عدد الفواتير | فترة |
| مطابقة الضريبة مع الحسابات | رصيد حساب الضريبة vs مجموع التقارير | فترة |
| مرتجعات ضريبية | فاتورة الأصل، وعاء سالب، ضريبة سالبة | فترة |

**معايير القبول:** مجموع التقرير = مجموع `invoices.tax_total` لنفس الفلترة
بالقرش، ومطابق لحركة حساب الضريبة.

## 9. القيود المحاسبية

عند ترحيل فاتورة بيع (أسعار شاملة):

```text
مدين  الصندوق/العملاء        total        (شامل الضريبة)
دائن  إيراد المبيعات         tax_base
دائن  ضريبة مخرجات مستحقة    tax_total
```

عند شراء (ضريبة قابلة للخصم):

```text
مدين  المخزون                tax_base
مدين  ضريبة مدخلات مستحقة    tax_total
دائن  الموردون/الصندوق       total
```

- المرتجع يعكس الاتجاه.
- فرق تقريب نقدي → حساب منفصل.
- يُتحقق `SUM(debit) = SUM(credit)` قبل الـCOMMIT.
- لا يُرحَّل قيد ضريبة بلا فاتورة مصدر.

## 11. الترحيل من النظام القديم

| القديم | الجديد | القاعدة |
|---|---|---|
| `currencies.tax` = 0 للجميع | `items.tax_category_id = vat14` | لا نستخدم 0 القديم؛ يُعيَّن التصنيف حسب قرار المالك |
| `companies.tax_no` فارغ | `settings.tax.registration_no` | **بيانات مطلوبة من المالك** |
| `inv.tax` / `inv_sub.taxperc` / `taxval` | لا تُنقل | الجداول فارغة |
| `tax_group` | `tax_categories` | لا قيم مستخدمة |
| `tab3tax` | لا يُنقل | إرث مطاعم/جدول |

> **تحذير مالي:** تحويل الأسعار من «بلا ضريبة» إلى «شاملة 14%» لا يغيّر
> ما يدفعه العميل، لكنه يخفض الإيراد المُعلن ويُنشئ التزامًا ضريبيًا.
> هذا قرار محاسبي/قانوني يحتاج تأكيد المحاسب قبل الترحيل.

## 12. اختبارات القبول

- [ ] 100.00 شاملة 14% → وعاء 87.72، ضريبة 12.28.
- [ ] 100.00 شاملة 14% + خصم 10% → وعاء 78.95، ضريبة 11.05.
- [ ] سعر غير شامل 100.00 + 14% → ضريبة 14.00، إجمالي 114.00.
- [ ] فاتورة بنسبتين (14% و0%) → مجموع الضريبة صحيح لكل بند.
- [ ] خصم رأس 5% موزَّع → مجموع البنود = الإجمالي بالقرش.
- [ ] 1,000 بند بأسعار كسرية → لا فرق قرش في المجاميع.
- [ ] مرتجع جزئي → ضريبة سالبة = نسبة من ضريبة الأصل.
- [ ] صنف معفى → ضريبة صفر وسبب مسجل.
- [ ] تغيير النسبة بعد البيع → الفاتورة القديمة لا تتغير.
- [ ] فاتورة شراء → ضريبة مدخلات وتكلفة صحيحة.
- [ ] تقرير الضريبة = مجموع الفواتير = حساب الضريبة.
- [ ] طباعة الفاتورة تحتوي كل الحقول الإلزامية وQR صالح.
- [ ] مستخدم بلا صلاحية لا يعدّل نسبة/تصنيفًا.
- [ ] `tax_total` لا يُقبل من الواجهة؛ يُحسب في الخدمة.

## 13. ما تبقى على المالك (3 أسئلة فقط)

| # | السؤال | التوصية |
|---|---|---|
| T-A | هل الأسعار شاملة الضريبة؟ | نعم (سعر الرف نهائي) |
| T-B | هل المنشأة مسجلة في ضريبة القيمة المضافة وتخصم المدخلات؟ | نعم → `tax.recoverable=1` |
| T-C | ما رقم التسجيل الضريبي والعنوان القانوني؟ | يُدخل في الإعدادات ويطبع |

بدون T-A/T-B يبقى الحساب قابلًا للتشغيل لكن التقرير الضريبي غير معتمد.

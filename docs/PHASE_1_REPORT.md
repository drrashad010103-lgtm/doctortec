### 4.2 قرارات تصميم (مثبَّتة ما لم يُعترض)

| # | القرار |
|---|---|
| DB-01 | `event_id` نصي `CHAR(36)` (UUIDv7) بدل `BINARY(16)` في البداية |
| DB-02 | تخزين UTC + `business_date` محلي |
| DB-03 | `invoice_no` فريد لكل `(branch, type, year)` |
| DB-04 | `stock_balances` Cache من `stock_moves` |

| DB-06 | **منع صارم** للبيع بالسالب بلا استثناء (D-09) |
| DB-07 | جدول واحد للعملاء والموردين بنوع |
| DB-08 | حفظ `cost_at_sale` في سطر الفاتورة |
| DB-09 | أسعار شاملة الضريبة افتراضيًا |
| DB-10 | نسبة ضريبية لكل تصنيف، ولقطة في البند |

### 4.3 أهم ما قررناه في التحليل

1. **`stock_moves` هو مصدر الحقيقة**، و`item_bal` مجرد Cache.
2. **كل عملية مالية/مخزنية حدث** له `event_id` ويُكتب في outbox داخل نفس المعاملة.
3. **الفروع إلزامية في المخطط**، لا تُضاف لاحقًا.
4. **لا LWW** للفواتير والمخزون؛ كشف تعارض وقرار.
5. **لا DDL من التطبيق**؛ الهجرات أداة CLI فقط.
6. **`DECIMAL` في كل حقل مالي** بدل `double`.
